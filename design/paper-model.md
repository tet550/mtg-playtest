# 紙モデル：コンポーネントはスクリプト、操作はすべてAI

2026-09-26。旧実装（main ブランチの `mtg.py` 一式）をプロトタイプとして扱い、中核を作り直すための設計メモ。このブランチには、デッキとカードの処理（`cardcache.py`・`decks.py` とその仕様書）とデッキのデータだけを残してある。

## 背景

プロトタイプは「スクリプトは記帳係、ルールはAI」という方針で始まった。しかし、AIの見落としを防ぐために自動処理が少しずつ増えた。SBA、P/Tの計算、ターン終了時の後始末、誘発候補の検出、戦闘ダメージ、詠唱回数、土地セットの警告などである。その結果、スクリプトがルールを**部分的に**知る状態になり、次の問題が起きた。

- **スクリプトが黙って誤り、AIがそれを信じる。** `combat damage --step regular` のバグで9点が誤って通り、相手がライフ-4で敗北と記録された。装備の `fx` を二重に登録すると、警告なしに P/T が膨らんだ。
- **組み合わせ方の知識が資料に溜まる。** 早見表に「〜は無い」「〜で停止」「後勝ちで上書き」といった注意書きが増え続けた。
- **範囲が決まらない。** どこまでスクリプトに入れるかを、機能ごとに毎回議論し直している。

## 方針

紙の対戦では、テーブル上の物はルールを知らない。カードは自分の P/T が修整されていることを知らず、ライフパッドは敗北を宣言しない。判断・計算・進行・記憶はすべてプレイヤーが担う。これをそのまま分担にする。

> **紙のとき、それは物の状態か、人が頭で行っていることか。**
> 物の状態ならスクリプト、人が行っていることならAI。

スクリプトはカードの意味を解釈しない。そのため、新しいメカニズムや自作カードが出ても、中核に実装を追加する必要がない。

## スクリプトの責任：物理的なテーブルが黙って保証していること

| 物理的な保証 | スクリプトでの形 |
|---|---|
| 1枚のカードは同時に1か所にしか存在しない | 移動元と移動先を必ず整合させる |
| ライブラリーの順番は誰にも見えない。手札は持ち主にしか見えない | 席ごとに見せる範囲を強制する |
| シャッフル・ダイス・コインは誰にも操作できない | seed つき乱数 |
| 山の積み順（ライブラリー・墓地・スタック）が保たれる | 順序つきの領域 |
| 物理的にできないことはできない | 不可能な操作だけを拒否する（空のライブラリーからは引けない、ダイスは負にならない） |

**スクリプトが操作を止めてよいのは、物理的に不可能なときだけ。** ルール違反では止めない。

## コンポーネント

| 紙のコンポーネント | スクリプトの状態 | 備考 |
|---|---|---|
| カード（印刷された文章・向き・表裏・どちらの面か） | オブジェクト：オラクル、タップ、裏向き、変身面、オーナー、コントローラー | オラクル文の表示は「カードを読む」ことにあたる |
| 各領域（ライブラリー・手札・戦場・墓地・追放・統率・スタックの山） | 順序と見える範囲を持つ領域 | スタックは「テーブル中央に積んだ山」 |
| トークン（トークンカード・代用品） | 作成時に書いた特性を持つオブジェクト | |
| カウンター（ビーズ・ダイス） | オブジェクトやプレイヤーに置く、名前つきの数 | |
| ダメージ用ダイス | オブジェクトに置く数 | 破壊の判定はしない |
| ライフパッド、毒・エネルギーの記録 | プレイヤーに置く数 | 0以下になっても何もしない |
| 重ね置き（オーラ・装備を下に敷く、「これで追放した」カードを下に置く） | オブジェクト間の「下に置いた」関係 | 帰還や許可の管理はしない |
| ブロッカーを攻撃クリーチャーの前に置く | 配置の関係 | ダメージの計算はしない |
| マーカー（統治者、イニシアチブ、昼夜カード、紋章カード、ダンジョン） | 名前つきの共有・個人マーカー | 意味は解釈しない |
| マナ用のダイス（浮いているマナ） | プレイヤーに置く色つきの数 | 用途の適否は判定しない |
| ターン・フェイズのトラッカー | AIが置く目印 | 自動では進まない |
| 付箋（カードに貼る「+2/+2 ターン終了時まで」など） | オブジェクトに貼る自由記述と、任意の期限の札 | 計算しない |
| メモ帳（遅延誘発・「ターン終了時に戻す」などの書き留め） | 自由記述のメモ（席・期限の札つき） | 期限が来ても自動では処理しない |
| 対戦の記録 | ログ、履歴、undo、結果の集計 | 紙にはない「録画」にあたる。テストツールとして必要なので持つ |

## AIの責任：上記以外すべて

- ターンの進行、優先権、パスの管理、ターン起因処理（アンタップ・ドロー・クリンナップ）の実行
- 唱える・起動する手順（コストの決定、マナを出すためのタップ、スタックへの移動）
- 解決の中身を操作で行うこと、解決後の行き先
- SBA のチェックと実行
- 誘発に気づくこと、メモすること、スタックに置くこと
- 継続的効果の計算（現在の P/T、付与された能力）と、期限が来たときに付箋を外すこと
- 戦闘ダメージの計算（接死・絆魂・トランプルを含む）
- 土地をプレイした回数・唱えた回数などの数え上げ
- 置換効果、コストの増減、すべての選択

## 境界で迷うものの判断

| 項目 | 判断 | 理由 |
|---|---|---|
| 現在の P/T の表示 | 印刷された P/T とカウンター・付箋を**並べて表示するだけ** | 紙のプレイヤーはカードとダイスを見て頭の中で足している。合計はAIが出す |
| 期限つきの付箋 | AIがトラッカーを進めたときに「期限切れの付箋 N件」と**表示する**。外すのはAI | 札とトラッカーを比べるだけで、ルールを解釈しない |
| 空のライブラリーからのドロー | 引く操作は拒否する。敗北するかどうかはAIが判断する | 物理的な不可能と、ルール上の結果を分ける |
| 1回の保存の単位 | AIが宣言した一連の操作をまとめて1回保存する（途中で失敗したら全体を適用しない） | 紙では1回の動作で複数の物を動かす。どこまでを1手とするかはAIが決める |
| コストの増減、解決後の行き先 | AIが操作として行う。スクリプトは記録だけ | ルールの解釈にあたる |

## 表示は最優先の成果物

人間はテーブルを一瞥すれば状態が分かるが、AIは毎回テキストを読み直す。**表示の出来が、そのままAIの精度になる。** 付箋・ダメージ・カウンター・関係・メモを、盤面の表示に常に出す。紙で「目印のダイスを置いておくと忘れない」のと同じ効果を、表示で担わせる。

## 補助層

誘発しそうな文章の列挙や、ダメージとタフネスを並べた表示などは、中核とは別の**補助層**に置く。紙のプレイヤーが使うオラクル検索アプリや計算機にあたる。補助層には次の3条件を課す。

1. 状態を変えない
2. 進行を止めない
3. 消しても中核が動く

補助層のヒントが誤っていれば、AIはそれに従って盤面を誤って操作しうる。自動で書き換える誤りは防げるが、誤ったヒントに従う誤りは防げない。そのため、中身はプロトタイプの検出ロジック（`sba`・`step_checks`・`enter_watchers` の検出部分）を移したものから始める。追加するのは、測定で見落としが確認された領域だけにする。

## 失うものと測り方

| 得るもの | 失うもの |
|---|---|
| ルールに関するバグが中核から消える | P/T の自動計算、ターン終了時の自動消去、SBA と戦闘ダメージの自動処理。その誤りがAI側に戻る |
| 「スクリプトが一部だけ知っている」ことによる食い違いがなくなる | バッチの切り方（ターン進行の位置、攻撃前に切る、など）を仕組みで止められない |
| コマンドが物の操作だけになり、注意書きの大半が不要になる | AIの推論量と、1手ごとのトークン消費が増える可能性がある |
| 中核が小さくなる | プロトタイプで検証済みの機能とテストを手放す |

プロトタイプ（main ブランチ）と同じ seed・同じデッキで比べる。指標は次のとおり。

- 訂正のメモの件数
- 対局後の確認で見つかった、誘発と SBA の見落としの件数
- 1ゲームあたりのトークン量
- 決着の誤り（誤った勝敗の記録）

移行の条件は「決着の誤りが0件で、見落としがプロトタイプ以下」とする。

最初の測定にはゴールドフィッシュが向いている。相手がいないので盤面が単純で、見落としがどれだけ増えるかを安く測れる。

## 作る順番

1. **中核**：コンポーネントの操作だけを持つ中核を作る。残したカードキャッシュ・デッキ登録を土台にし、乱数・表示・履歴を新しく実装する。
2. **付箋とメモ帳**：プロトタイプの `mod`・`grant`・`fx`・`effect`・`pending`・`remind` の役割を置き換える。
3. **補助層**：プロトタイプの検出ロジックを、状態を変えず進行も止めない補助コマンドとして移す。
4. **AI側の資料**：ステップごとのチェックリストを作る。
5. **比較**：上記の指標でプロトタイプと比べる。

## 残したコードの既知の問題

- `decks.py verify` は確認だけでなく登録ファイル（`decks/*.json`）を書き直す。カードキャッシュがない状態で `--offline` を付けて実行すると、タイプやマナ総量が空になった状態で上書きされる。確認と書き込みを分ける。
- `decklists/README.md`・`card-schema.md`・`deck-schema.md` には、削除した資料へのリンクが残っている。
