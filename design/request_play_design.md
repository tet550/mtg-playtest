# 依頼だけで遊ぶ席の設計

web_design の「人間の行動は先に記録し、審判がまとめて確かめる」を置き換える。

## 方針

- **席の Player は卓（盤面）に書けない。** 書けるのは審判への依頼・回答と、盤面を変えない宣言だけ。
  盤面を変えるのは審判だけで、**例外を置かない**（マリガン・キープの下に置くカードも審判が処理する。サーバーの定型の処理は作らない）
- **依頼は GUI の下書きで組み立てる。** 土地を出す・唱える・攻撃する・1 枚引く…は、ブラウザの中で依頼の行（人が読める文）を
  足していく操作になる。送ると1つの依頼になる。下書きは op に展開しない（審判が文を読んで卓に書く）
- **隠れた情報は下書きでは「？」。** 1 枚引くなどは、画面の手札に「？」を足すだけ。中身は審判が処理した後に、席の view として初めて届く
- **送る前は取り消せる、送った後は取り消せない。** 下書きの行は Undo で新しい方から外せる。送った依頼は取り下げない
- **審判の処理中は、次の下書きを組み立てない。**

今の問題（ターン0や相手のターンでも引ける、相手のライブラリーを見られる、勝敗・ターンを直接書ける）は、サーバーが席の
書き込みを絞ることで、GUI を経由しない API の呼び出しも含めて塞がる。

## 席が書けるもの（サーバーの許可リスト）

| 書けるもの | 条件 | 中身 |
|---|---|---|
| `declare intent` | 質問されていない・審判の処理待ちでない | 依頼の文（下の「依頼の形」） |
| `declare answer` | 自分への質問がある | 回答（今のまま） |
| `pass` | 自分に優先権がある・審判の処理待ちでない | 対応しない |
| `declare keep` | ターン0・まだキープしていない | キープの宣言。マリガンの後なら審判が下に置くカードを聞く |
| `declare mulligan` | ターン0・まだキープしていない | マリガンの宣言。手札を戻す・シャッフル・引き直しは審判が書く |
| `declare concede` / `say` | いつでも | 今のまま |

ブロックしない・攻撃しないは宣言ではなく、依頼の1行（`{"kind": "other", "text": "ブロックしない"}`、その後 `pass`）で送る。
宣言だけでは進行（ステップを進める）が誰にも書かれないため。

ブロックは審判の質問（`ask`）で選ばせない。審判は攻撃を書いたら `declare_blockers` へ進めて防御側に優先権を渡して止め、
防御側が GUI（自分のクリーチャー → 攻撃クリーチャーの順に押す。下書きの `block` 行）か AI の依頼でブロックを送る。
防御側が決めるまで（自分のブロックが無く、ブロックの依頼も `no_block` も出していない間）は自動パスしない
（`play.blocks_undecided`）。ブロックを選ばせる `ask` は、審判の返答の適用で断る。

- これ以外の op（`move`・`draw`・`shuffle`・`tap`・`cast`・`step`・`player_set`…）が席の Batch に1つでもあれば 403
- 宣言の op も、`declare` の上の kind 以外（`ruled`・`ask` などの審判のもの、自由な kind）は 403
- 条件（ターン0・質問・処理待ち）はサーバーが確かめる。GUI がボタンを隠すのは表示の都合だけで、守りはサーバー
- 席は op を送らない。席の API（下の「API」）は卓と別の言葉で書き、サーバーが上の宣言に変換する（GUI と AI の席の共通の入口。
  今の `prompt.intent_ops` を置き換える）。今の `mulligan`（move・shuffle・draw を書く）と `keep` の `bottom`（下に置く move）は外し、宣言だけにする
- 席の取り消し（`POST undo`・`play.undo_refusal`・`reveals`）は外す（卓に書いた依頼は取り消さない）

### ゲーム開始

- マリガンの宣言が出たら審判の番（`waiting_on` = judge）。審判は手札を戻し・シャッフルし・引き直して `ruled` を書く。
  その間、その Player は次の宣言をしない（処理待ち）
- 全員がキープしたら、今どおり審判の番（`game_start_pending`）。審判はマリガンした Player に下に置くカードを聞き（`ask` の `cards`）、
  開始時の手札から使うカードを処理し、先攻の T1 を始める（judge.md の今の手順のまま）

## 下書き（ブラウザの中だけ）

- 下書きは**依頼の行の列**。1行は、送る `plan` の1行（下の「席の API の形」）そのもの。画面の印（「出す予定」・「？」）は
  `kind` と `cards`・`count` からブラウザが決める（送るのは `plan` だけ）
  ```js
  { kind: "play_land", cards: ["#c133"], text: "<Forest> (#c133) を出す" }
  { kind: "draw", count: 1, text: "1 枚引く" }                    // 手札に「？」1 枚、ライブラリー −1（予定）
  { kind: "cast", cards: ["#c96"], targets: [], text: "<Grizzly Bears> (#c96) を唱える 対象: なし" }
  ```
- メニューは今の GUI とほぼ同じ（「土地として出す」「唱える…」「攻撃する」「1 枚引く」…）。押すと卓に書く代わりに行を足す。
  文の作り方は、今の依頼文の「行動: 1. …」と同じ（`describe`。カード名と id を書く）
- 画面: 下書きの行は、送る前から**画面の上だけ**で盤面に仮に反映する（play.js の `preview`。卓の view は変えない）。
  土地を出す（手札 → 戦場）・唱える（手札 → スタック）・起動（スタックに能力）・攻撃（戦闘に加え、警戒でなければタップ）・
  引く・切削（ライブラリーの枚数）。仮のカード・項目は薄い色と破線で出し、押すと「予定を外す」。それ以外の行は印と文だけ。
  送った依頼も、審判が処理するまで同じように出したまま。依頼の欄に行を番号付きで並べる
- 「？」: ライブラリーの `kind`（`draw` など）の行があれば、手札の欄に「？」のカードを足し、束の枚数の横に「−N（予定）」を出す。「？」は選べない
  （唱える・出す・対象にするの対象にならない）。引いたカードを使いたいときは、そこまでで送り、審判の処理を待つ
- **Undo**: 下書きの最後の行を外す（何度でも。卓には触らない）。「全部捨てる」も置く
- 下書きは localStorage に、対局・席ごとに置く（再読み込みで消えない）。審判の処理で盤面が変わり、行に書いたカードが
  もう同じ領域に無ければ、その行に印を付ける（送る前に本人が直す）

### 下書きにする操作（今の GUI の直接の操作から）

| 今（卓に書いていた op） | 下書きの行 |
|---|---|
| 土地として出す（`move`） | 「<X> を出す」 |
| 唱える…（`cast`・対象・支払い） | 「<X> を唱える 対象: … 支払い: …」 |
| 能力を起動…（`stack_push`） | 「<X> の能力を起動 …」 |
| 攻撃・ブロック（`attack`・`block`・`step`） | 「<X> で <p2> を攻撃」「<X> で <Y> をブロック」 |
| タップ・アンタップ・カウンター・Note・領域の移動・ダメージ・ライフ・コントロール | 「<X> をタップ」などの文（効果の処理を頼むとき用） |
| スタックの解決（`stack_remove`）・対象を選ぶ（`link_add`） | 「<スタックの X> を解決」「<X> の対象を <Y> に」 |
| 1 枚引く・N 枚引く・上から N 枚を見る・一番上を公開・切削・シャッフル | 「1 枚引く」など（`hidden` 付き） |
| 次のステップへ | 依頼の「その後」（「戦闘へ」「ブロックへ」「メイン2へ」…） |
| 自由な文 | 「補足」（今のまま） |

## API

### 今

| 系統 | 入口 | 誰が | 書ける範囲 |
|---|---|---|---|
| HTTP（`serve`） | `GET /api/games`・`config`・`image`・`symbol`・`oracle` | 誰でも | 読むだけ（対局の一覧・カードの情報） |
| | `GET /api/games/<g>/view`・`timeline`・`log`・`stops` | 鍵の対局は、その席の鍵だけ。鍵の無い対局は誰でも（judge の全情報も） | 読むだけ |
| | `GET /api/games/<g>/events`（SSE） | 誰でも（鍵を見ない） | version・cursor だけ |
| | `POST /api/games/<g>/apply` | 席の鍵（`--play`） | **任意の Batch**（actor を席に固定、`proxy`・`ruled`・`ask` だけ拒否） |
| | `POST /api/games/<g>/undo` | 席の鍵 | 自分の直前の Act（`undo_refusal`） |
| | `POST /api/games/<g>/stops` | 席の鍵 | 止める場所（非公開のファイル） |
| CLI（対局フォルダを直接） | `apply`・`undo`・`replay`… | その PC の人・プロセス | **何でも**（審判も席も。鍵を見ない） |
| | `next`・`answer`・`auto` | 審判と AI の席を回すプロセス | 審判の Batch、AI の intent / direct の返答 |

席の守りは「鍵で席を名乗る」までで、書ける中身は HTTP の `apply` も CLI も絞っていない。

### これから

| 入口 | 誰が | 中身 |
|---|---|---|
| `GET` の各入口 | 今のまま | `events` は鍵なしのまま（version・cursor だけ。`auto --watch` の審判が席の鍵を持たずにつなぐ。審判の鍵ができたら絞る） |
| `POST /api/games/<g>/request`（新） | 席の鍵 | 依頼（下の「席の API の形」） |
| `POST /api/games/<g>/declare`（新） | 席の鍵 | 決定の宣言（キープ・マリガン・パス・ブロックしない・攻撃しない・投了・発言） |
| `POST /api/games/<g>/answer`（新） | 席の鍵 | 審判の質問への回答 |
| `POST /api/games/<g>/stops` | 席の鍵 | 今のまま |
| `POST /api/games/<g>/apply`・`undo` | — | **外す**（席が Batch を書く入口を無くす） |
| CLI `apply`・`undo` | 審判（`--as judge`） | 鍵の対局では、席を actor にした Batch（`--as p1`・batch の `actor: "p1"`）を断る。席の操作は `answer`（intent モード）だけ |
| CLI `next`・`answer`・`auto` | 審判と AI の席 | 審判の Batch は今のまま。AI の席は intent モードだけ（direct モードは鍵の対局では断る） |

- CLI はファイルを直接触るので、同じ PC の上では本当の守りにならない（ローカルでの約束事）。サーバーで動かすときは、
  審判も HTTP の入口（審判の鍵）にし、ファイルに触れるのはサーバーだけにする（web_design の「サーバーで動かすときに残っていること」）
- GUI と AI の席が同じ形で送るので、AI の席を HTTP に移すときも同じ入口を使える

### 席の API の形

席の API のキーは、卓の言葉とぶつかるもの（`action`・`note`）だけ避け、ほかは今の言葉のまま使う。

```json
POST /api/games/<g>/request
{"seat": "p1", "expect": 283, "then": "pass", "comment": "補足の文",
 "plan": [
   {"kind": "play_land", "cards": ["#c133"], "text": "<Forest> を出す"},
   {"kind": "cast", "cards": ["#c96"], "targets": [], "text": "<Grizzly Bears> を唱える"},
   {"kind": "draw", "count": 1, "text": "1 枚引く"},
   {"kind": "other", "text": "<X> の能力で …"}]}

POST /api/games/<g>/declare
{"seat": "p1", "expect": 283, "kind": "mulligan", "text": ""}

POST /api/games/<g>/answer
{"seat": "p1", "expect": 290, "text": "はい", "cards": ["#c12"]}
```

| キー | 意味 | 卓では |
|---|---|---|
| `expect` | 見ていた盤面の位置（今の cursor） | `expect`（違えば 409） |
| `plan` | 依頼する行動の列（下書きの行） | `declare intent` の `plan` にそのまま残す（engine は中身を見ない。op に展開しない） |
| `plan[].kind` | 行動の種類（下の表） | — |
| `plan[].cards` | 使うカード（席が知っている id だけ。`can_reference` で確かめる） | — |
| `plan[].targets` | 対象（カード・Player・スタックの項目） | — |
| `plan[].count` | 枚数・数 | — |
| `plan[].text` | その行の文（人と審判が読む） | 依頼文の「行動: 1. …」 |
| `then` | その後（`continue`・`pass`・`end_turn`、またはステップ名 `beginning_of_combat`・`declare_blockers`・`main2`・`end`） | 依頼文の「その後: …」 |
| `comment` | 補足の文 | 依頼文の「補足: …」 |
| `declare` の `kind` | `keep`・`mulligan`・`pass`・`concede`・`say`（ブロックしない・攻撃しないは、審判が進行を書くので依頼の1行で送る） | `pass` は op の `pass`、ほかは同じ kind の `declare` |
| `answer` の `text`・`cards` | 質問への答え・選んだカード | `declare answer` |

`plan[].kind` の種類（少数に保ち、当てはまらなければ `other` と `text`）:

| `kind` | 下書きのメニュー | 下書きの表示 |
|---|---|---|
| `play_land` | 土地として出す | 「出す予定」 |
| `cast` | 唱える… | 「唱える予定」 |
| `activate` | 能力を起動… | 「起動予定」 |
| `attack` / `block` | 攻撃する・ブロックする… | 「攻撃予定」「ブロック予定」 |
| `resolve` / `target` | スタックの解決・対象を選ぶ | スタックの項目に印 |
| `draw` / `look` / `reveal` / `mill` / `shuffle` / `search` | ライブラリーのメニュー | 「？」・束の「−N（予定）」 |
| `other` | タップ・移動・カウンター・ダメージ・ライフなど | 文だけ |

## 依頼の形

サーバーは `plan` の `text` と `then`・`comment` から今の依頼文を作り、`declare intent` の `text` にする。`plan`・`then` も同じ宣言に
残す（審判のプロンプトと、送った依頼の読み取り専用表示に使う）。

```
行動: 1. <Forest> (#c133) を出す 2. <Grizzly Bears> (#c96) を唱える 3. 1 枚引く
その後: パス
補足: …
```

- 送るボタンは「審判に依頼」の1つ。`then` は下書きの最後の行で決まる（「その後」の行 `kind: "then"` の `end_turn`・`pass`、
  ステップを進める行ならそのステップ。無ければ自分のターンは `continue`・相手のターンは `pass`、相手のクリンナップは `turn_start`）。
  下書きが空でパスになるなら依頼にせず `declare` の `pass` を送る（`play.js` の `toRequest`・`requestAction`）
- 公開範囲は今の `intent` と同じ（本人と審判だけ。`info.PRIVATE_KINDS`）。相手は審判の処理後の盤面しか見ない。
  そのため `play.visible_cursor` の「他の Player が直接記録した行動を隠す」処理は要らなくなる
- 送るときの `expect` は今の cursor。盤面が変わっていたら 409 で断り、下書きは残したまま「盤面が変わりました。確かめて送り直す」と出す
- 送ったら下書きは「送った依頼」として依頼の欄に読み取り専用で残し、審判の `ruled` が来たら消す（その間は Undo も新しい行も無し）

## 審判

- judge.md の「未確認の行動を確かめる」を「依頼の行動を処理する」に置き換える。行動を古い順に、ルールに沿って卓に書く。
  足りない処理（マナの Note・コストの支払い・タップイン・誘発・状況起因処理）を補い、Player に選ばせることは `ask` で聞く。
  できない行動（2枚目の土地・払えない呪文・引けない場面の「1 枚引く」）は書かずに、`message` で理由を伝える
- 「1 枚引く」などの隠れた情報の行動も、審判が場面を判断して書く（効果で引く・ドロー・ステップの追加のドローなど）。
  理由が分からなければ `ask` で聞く。引いたカードは label・message に書かない（今の約束のまま）
- 卓に未確認の行動は無くなるので、戻す操作は要らない
- `prompt.unreviewed` と、その件数で審判を呼ぶ `prompt.next_role` の分岐は外す。審判を呼ぶのは依頼（`REQUEST_KINDS`）と、
  今どおりのゲーム開始・全員パスでスタックが残ったときだけ

### 計画の途中で止めた後（割り込み）

依頼（計画）の行は、審判が途中で止めることがある（相手の止める場所・ブロック・引いたカードを本人が見て決める所）。

- 審判は止めるとき、返答の `rest` にまだ書いていない行の番号を書く。卓は `ruled` に `of`（計画の intent の seq）と
  `rest` を残す。`of` を付けるのは、計画そのものを処理したとき（本人の依頼・その続き・本人の呪文の解決）だけ。
  相手の依頼（割り込み）の処理では付けない。intent の宣言は `plan`（行）と `then` を持つ
- 相手が対応しなかった（パス・ブロックしない）: 卓が審判に続きを回す（`play.continue_pending`）。審判は残りの行と「その後」を書く
- 相手が割り込んだ（行動のある依頼。「ブロックしない」だけのものは除く）・本人が決める所で止めた: 続けない。本人の番になり
  スタックが空なら、残りの行と「その後」を本人に戻す（`play.resume` → view の `resume`）。GUI は下書きが空なら自動で戻し、
  下書きがあれば「下書きに足す／捨てる」を出す。一度戻した・捨てた計画は出さない。直して「審判に依頼」で送り直すと、新しい計画になる。
  AI の席はプロンプトの「途中で止まったあなたの計画」で読む
- 審判が `rest` を書かなかった（どこまで済んだか分からない）ときは、割り込みがあれば計画の全部を戻し、済んだ行を本人が外す

## AI の席

AI はすでに intent モード（`player_intent.md`）で依頼の文だけを送っている。返答の形を席の API にそろえる
（今の `{"action", "text", "memo"}` を `{"request": {"plan", "then", "comment"}}`・`{"declare": {"kind", "text"}}`・`{"answer": {"text", "cards"}}` と `memo` に）。
最初は `plan` を `other` の1行（`text` に今の文）だけで送ってよい。マリガン・キープは宣言だけにする（下に置くカードは審判の `ask` に答える）。direct モード（`player.md`。席が Batch を
直接書く）は、鍵で守る対局（`seats.json` がある対局）では使えないようにする（審判の無い CLI の一人回し・検証用に残す）。

## 待ち時間と費用

審判（LLM）を呼ぶのは、今と同じく依頼を送ったときだけ。変わるのは次の2つ:

- 送ってから審判が処理するまで、盤面は変わらない（今は行動が先に盤面に出ていた）。その間は「審判の処理待ち」を出し、
  送った依頼の行を読み取り専用で見せる
- マリガンが審判の番になる（今は席がその場で引き直していた）。1回のマリガンに審判の呼び出しが1回増える

## 今の仕組みから外すもの・変えるもの

| 今 | これから |
|---|---|
| 席が卓に op を書く（play.js の `act`） | 下書きに行を足す |
| 未確認の行動（`play.routine`・`prompt.unreviewed`・GUI の `unreviewed`） | 外す |
| 席の取り消し（`POST undo`・`undo_refusal`・`reveals`） | 下書きの Undo（ブラウザの中） |
