# 観戦ビューアの設計

読み取り専用の Table Engine ビューア。ゲームの正本は対局フォルダ、公開範囲の判定は
Python の `info.player_view` に置き、ブラウザは受け取った view の再生と描画を担当する。

## 見直した点

従来の `app.js` は通信、差分復元、描画、画面操作を同時に扱っていた。
配信方式の分岐が描画にも入り、通信中に席・対局が変わると古い結果を反映できた。
責務の境界を作り、変更時に確認する範囲を小さくする。

| ファイル | 責務 |
|---|---|
| `web.py` | PlayerView・時系列・Log の生成、HTTP/SSE 配信、静的書き出し |
| `web/source.js` | ローカル API と静的 JSON の違い、画像・オラクル、更新購読、古い要求結果の破棄 |
| `web/timeline.js` | キーフレームと差分から指定位置の view を復元。DOM・通信に依存しない |
| `web/render.js` | カード、盤面、戦闘、スタック、Log の DOM 描画 |
| `web/app.js` | 選択状態、読み込み結果の反映、再生、ユーザー操作、初期化 |
| `web/dom.js` | DOM 要素の生成と ID 検索 |

データは `source → app → Timeline → render` と流れる。
描画からの Log 移動はコールバックで app に戻す。循環 import は作らない。
画面上の状態は app が作成して renderer に渡し、カード名索引や攻撃表示などの派生値は
renderer が view から更新する。汎用的な状態管理ライブラリは導入しない。

## 読み込みと再生

- 対局と席を要求開始時に固定し、時系列と Log をまとめて読み込む。Log の取得は judge のみ。
- 新しい要求が始まったら、それより古い要求の成功・失敗は画面に反映しない。
- 対局・席の変更時は再生を停止し、古い盤面・詳細・Log を消して購読を張り直す。
- カード詳細も、後から選んだカードや変更後の view を古いオラクル応答で上書きしない。
- 再生中の移動では通信せず、Timeline のキャッシュから復元する。
- キーフレーム間隔と差分形式は既存のまま。ルートの置換は古いキーを残さず置き換える。

HTTP の時系列と Log は別リクエストのままなので、CLI の書き込みと完全に同一時点の
スナップショットを保証するものではない。更新は既存の SSE により再取得する。
厳密な整合性が必要になった場合はサーバー側で一つのスナップショットとして返す。

## 維持した構成と判断

ビルド不要の ES modules と Python 標準ライブラリを維持する。小規模な読み取り専用画面に
フレームワーク、バンドラー、汎用イベントバスは追加しない。
Python 側は既に Viewer・Handler・export_site に役割が分かれているため、今回さらに分割しない。
CSS とレイアウトは維持し、描画の部分更新は性能上の必要性が判明した時点で検討する。

`mtgtable/web/` がソースの正本、`docs/static/` は公開用コピー。
export は JS/CSS をまとめてコピーするため、モジュール追加のたびにコピー対象を列挙し直す必要はない。
既存の公開データを変えずにフロントだけ更新する場合も、JS/CSS を一式同期する。

## 検証

`python -m unittest discover -s tests` で API、席ごとの公開範囲、静的書き出しを検証する。
`node --test tests/web.test.mjs`（Node.js 24）で差分復元、キャッシュ、要求の競合、配信方式、
購読の終了を検証する。Node.js はテスト用であり、利用者が観戦するためには不要。
