# 効果・関連付けの改善案

2026-09-09。調査時点の設計案と今後の拡張方針。実装済みの操作と制限は [操作ガイド](../.claude/skills/mtg-playtest/references/relations.md) を正本とする。世代付き参照、共通の移動経路、fxの導出計算、関連追放・帰還・通常のプレイ許可を実装済み。コピー・能力喪失・継続的コントロール変更・置換効果・フェイズアウト等は個別裁定を要する。

## 現状

対象: `.claude/skills/mtg-playtest/scripts/mtg.py`。

| 項目 | 実装 | 残る問題 |
|---|---|---|
| 装備・オーラ | 各objectの `attached_to` に対象oidを記録 | 対象種別・領域・エンチャント条件をattachで検証しない。プレイヤー参照を扱えない |
| 付け替え | `cmd_attach` が `drop_attached_mods` を呼ぶ | 旧対象の該当src・attachedのmod/grantは消えるが、新対象への付与は手動。削除内容も付け替え出力に出ない |
| 修整・能力 | 対象の `mods` / `grants` に値・until・srcを保存 | srcの実在・実際の装備先との一致は保証しない。式ではなく数値なのでカウンター変化に追従しない |
| 訂正 | `mod --set` は同じsrc・untilの合計を置換 | 同じ発生源の別効果を区別できない。`grant --clear` は他の発生源分も全削除 |
| 戦場離脱 | `cmd_move` とSBAの死亡処理で一時状態と装備関係を整理 | 領域移動処理が分散。通常のオーラが外れた場合の墓地送りはSBAで自動処理されない |
| 追放 | 通常の領域移動 | 発生源・能力・追放したカード群・帰還条件・プレイ許可の構造化記録がない |
| その他の効果 | `effect add` はtext・until・turnのメモ | 計算・関連付け・解決待ちを管理しない |
| 同一性 | 領域移動後もoidを再使用 | 明滅後の新しいオブジェクトと古い効果の参照を区別できない |
| 期限 | eot / permanent / attached。eotの除去はturn next内 | 次の終了ステップ、次の自分のターン終了まで等を表現できない |
| スタック能力 | 専用objectと対象を書いたnote | 発生源の世代・能力識別子・構造化された対象・離脱前情報を持たない |

確認: `test_bo1_regressions.py` の5テスト成功。付け替えで該当発生源だけの修整・付与が消えること、他の発生源が残ること、同じ対象へのattachでは消えないことを含む。過去対局で消えなかった原因の特定は今回の調査には含まない。

## 推奨する構造

### 1. カードの識別と、ルール上のオブジェクトの識別を分ける

表示・入力に使うoidは維持し、内部参照を `{oid, incarnation}` にする。領域移動で世代を進める。コントロール変更・変身・フェイズアウトを通常の領域移動にしない。領域移動を追跡できるルール上の例外は、特定のイベントが返す旧参照→新参照の対応を明示的に受け取る。

### 2. 関係・効果・解決待ちを分ける

- 関係: attachment、関連する追放カード群など。「どれと結び付いているか」を持つ。
- 効果: effect_id、発生源の世代、ability_id、適用先、条件、期限、演算、タイムスタンプ、根拠を持つ。発生源が消えても続く解決済み効果は保持する。
- 解決待ち: 誘発、遅延誘発、選択、未対応処理を記録する。関連付けの存在だけで解決済みにしない。

同じ発生源・同じ能力が複数回解決したものは別effect_idとする。訂正はeffect_id単位で置換・取消し、新規解決は別IDを発行する。これにより冪等な訂正と、意図した重複適用を両立する。

### 3. 装備の効果は発生源に一度登録し、現在値を導出する

概念例（実行用CLIではない）:

```yaml
effect_id: E12
source: {oid: 3, incarnation: 1}
ability_id: equipped_bonus
kind: continuous_static
recipient: attached_object
active_when: source_on_battlefield_and_attachment_valid
operations:
  - modify_pt: {power: 1, toughness: 0}
  - grant_keyword: trample
```

装備先A→Bなら関係の更新だけで、Aへの適用がなくなりBへ適用される。A/Bのmodsを移送しない。カウンター依存は、確認済みのカード定義に限定した安全な式で表す。任意Pythonやカード文章の自動推測は使わない。規則自体が意味を定めるカウンターとカード固有のカウンターを区別する。

カード定義のテンプレートは再利用できるが、各対局のeffect instanceとは分離する。未登録なら最初の適用時に「未設定」と明示し、AIがテキストを確認して登録する。複雑な条件を無視して有効扱いにしない。

P/T表示・能力判定・戦闘・SBAが同じ導出関数を参照する。能力を失わせる効果を加える場合は、オラクル文字列にキーワードがあるだけでhas_kwが真になる経路も改める。

### 4. 追放は原因・カード群・後続処理を分けて記録する

| 意味 | 必要な扱い |
|---|---|
| 発生源が戦場を離れるまで追放 | 発生源の当時の世代と帰還条件を保持。条件発生時の帰還は誘発と区別。追放の解決前に条件が成立済みなら追放しないケースも扱う |
| 戦場を離れたとき、追放したカードを戻す | 関連する能力を識別し、帰還の誘発をスタックへ。打ち消された場合は戻さない |
| 次の終了ステップに戻す | 遅延誘発を保持。作成元がなくなっても存続する場合に対応 |
| 追放したカードをプレイしてよい | 関連付けとは別のpermissionとして、誰が・どの世代を・いつまで・土地可否・タイミング・コスト条件を持つ |
| 刻印など、追放したカードを参照 | source instance + ability/link groupで限定。追放回ごとの履歴と、能力が参照する集合を区別 |

追放カードが別領域へ移動したら旧参照は帰還・許可の対象から外す。同じカードが再び追放されても古い関連を復活させない。複数枚・複数回の追放を扱う。裏向きカードの閲覧許可は関連付けとは別に保持する。

### 5. 他の効果へ拡張する際の境界

- ロードなどの常在型強化は現在の条件で対象を再評価する。解決時の「全クリーチャーにターン終了時まで+N/+N」はその時点の対象集合を保持し、後から出たものへ広げない。
- コントロール変更は所有者・コントローラー・領域を分離して管理する。期限切れは単にownerに戻すのでなく、残る効果から計算する。
- 基本P/T設定、加算、能力の追加・喪失、種類変更、コピーは種類別とタイムスタンプを持つ。依存関係を含む未対応の相互作用では結果を確定せず、裁定待ちを表示する。
- 置換・軽減は移動やダメージの確定前に適用する。複数候補の選択・順序をAIが決めてから確定する。確定後の帳尻合わせにしない。
- 通常のオーラ、装備、授与、プレイヤーに付くオーラを区別する。対象を取る条件と、付いていられる条件を混同しない。
- クリンナップでの期限切れと、終了ステップの誘発を別イベントにする。追加ターン・追加ステップでも「次の」が正しくなるイベント識別子を使う。

## 更新と表示

領域移動・付け替え・カウンター変更・ステップ進行を共通の状態更新経路へ集約する。既存のmove、SBA、draw、mill、search、stack等に残る直接変更を段階的に置き換える。

処理は入力検証→置換や選択の確認→同時イベントの確定→効果再計算→適切なルール上の時点でSBA反復→誘発のスタック登録とする。離脱前の情報を保存し、同時死亡を1体ずつ別時点の盤面として扱わない。呪文解決の途中に不要なSBAや優先権を挿入しない。

一操作の関連変更は一つの保存・undo単位にする。選択待ちはpending状態として明示し、完了した変更は再実行しない。バッチ全体を無条件に一括適用せず、未知の判断箇所で止める。

通常出力例: 「装備3: A→B / A: +1/+0・トランプル終了 / B: +1/+0・トランプル適用」。詳細表示ではeffect_id・発生源・能力・期限・計算根拠を辿れるようにする。追放表示も発生源別のカード群と帰還条件を出す。

整合性検査は、存在しない参照、旧世代への残存効果、不正なattachment、期限切れpermission、未処理の帰還等を報告する。直せることと裁定が必要なことを区別し、推測で効果を消さない。

## 導入順と受入条件

1. 現行の安全性改善: attachで除去内容を表示、srcと装備先の検証、能力取消しを発生源・効果単位へ。早見表と本文例を同時更新する。
2. 基盤: 世代付き参照、共通の移動経路、effect_id、離脱前情報。save/load・undo・バッチ・compactの整合性を検証する。
3. 装備・オーラ: 定数修整・キーワード・必要なカウンター依存を導出。以後付け替えでmod/grantを再入力しない。
4. 関連追放: 帰還効果、帰還誘発、遅延誘発、プレイ許可を順に対応する。
5. 全体強化・期限・コントロール変更を広げる。コピー・依存関係・置換効果は明示した対応範囲から拡張する。

既存状態はschema_versionを付けて移行する。正しいsrc付きattached効果だけを確認可能な範囲で変換し、既存の手入力との二重計上を防ぐ。発生源不明の効果は要確認として残す。過去の明滅履歴はoidだけから推測して復元しない。

必須の振る舞いテスト:

- 複数装備のうち1つだけ付け替え、同じ対象へ再attach、カウンター増減、装備の離脱、対象の同時死亡。
- オーラの不適正化と授与の例外、プレイヤーへの装着、コントロール変更、明滅・フェイズアウトの違い。
- 発生源が追放解決前に離脱、帰還誘発の打ち消し、複数枚追放、追放カードの別領域移動と再追放、発生源の明滅。
- ロード強化と解決時の全体強化の違い、能力喪失と他の付与、終了ステップとクリンナップの違い。
- 保存・再開・undoで関係と導出結果が一致し、同一訂正の再適用では重複せず、別の能力解決は重複できる。
