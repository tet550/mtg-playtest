# 多言語化（英語・日本語）の計画

Web の画面を英語と日本語で使えるようにする。言語は初回はブラウザの言語（`navigator.language` が `ja*` なら日本語、
それ以外は英語）で決め、ヘッダーの切り替えで変えて localStorage（`mtgtable.lang`）に残す。

## 方針

**卓に書くもの・AI に渡すものは言語に依らない形（英語か、構造化した値）にし、翻訳は画面に出す時だけ行う。**
対局の記録は見る人の言語に関係なく1つで、審判の判断と画面の表示が同じものを元にする。

| もの | 卓・AI での形 | 画面での扱い |
|---|---|---|
| UI の文言（ボタン・メニュー・ページ） | — | 辞書で訳す |
| カード名・オラクル・画像 | 英語名が正本（識別子）。AI には英語のオラクル | 日本語のときは日本語版を重ねる（無ければ英語） |
| AI が書く Note・カウンターの種類・トークン名 | **英語で統一** | **訳さず、書かれたとおりに出す**（辞書の翻訳はペンディング） |
| 約束事の印（依頼の `then`・タップの有無・自動パスなど） | 文の中の日本語から、フィールド・フラグへ | 表示用の文は辞書で訳す |
| AI の宣言・ラベル・質問（人に向けた文） | 今は日本語 | そのまま出す（段階 7 で対局の言語で書かせる） |

## 今の状態（調べたこと）

| 場所 | 量（コメントを除いた日本語の行の目安） | 備考 |
|---|---|---|
| `web/index.html` | 約 50 | ヘッダー・再生バー・小窓の見出し・権利の表記・`<meta>` |
| `web/play.js` | 約 270 | メニュー・操作パネル・下書きの行の文・ステップ名・止める場所 |
| `web/render.js` | 約 50 | ゾーン名・フェイズ／ステップ名・戦闘・スタック |
| `web/lobby.js`・`history.js`・`decks.js`・`site.js`・`app.js` | 計 約 110 | サイトの各ページ・トースト |
| `web/legal.js` | 約 45 | 利用規約・プライバシー（法的な文） |
| サーバーの例外（`raise …("…")`） | `history.py` `decks.py` `lobby.py` `web.py` `worker.py` `llm.py` など 約 30 | API の `{"error": "…"}` がそのままトーストに出る |
| AI のプロンプト（`prompts/*.md`・`prompt.py`） | 多い | 日本語で書かれ、審判・AI の席の返答（宣言・ラベル・質問）も日本語になる |
| AI が書く Note・カウンター | — | カウンターの種類は英語（`+1/+1`・`loyalty`）。Note は英語が多いが、プロンプトが日本語なので日本語も混ざる |
| カード名・オラクル・画像 | — | 英語のみ。`carddb.py` が Scryfall から英語名で引いてキャッシュ（`cards/`）。画面は `/api/oracle?name=`・`/api/image?name=`、静的書き出しは `data/cards.json`（画像の URL）とブラウザからの Scryfall 直接取得（`source.js` の `scryfallOracle`） |

カード名は表示だけでなく **卓の識別子** でもある。対局の状態（`Card.name`）・デッキリスト・キャッシュのファイル名・
AI のプロンプト・Log のラベルや Note（`<Name>` の書き方）がすべて英語名でつながっている。

文言が「表示」だけでなく **約束事（プロトコル）としても使われている** 所がある。ここは訳す前に直す必要がある。

- 依頼の文（request_text）の印: `その後: …`・`… まで進める`・`行動:`・`ブロックしない` を `play.py`（`request_then`・`_no_action`）が正規表現で読む
- 下書きの行の文: `をタップして`・`をタップする`・`をアンタップする`・`タップしない` を `play.js`（`preview` など）が読む
- 卓の記録に保存される日本語のラベル: `自動パス（止める場所に当たらない）`・`投了`・`発言`・`審判: …`（`prompt.py` の `startswith("審判")`）
- `worker.py` の `reason == "決着"`

公開用コピーの `docs/static/` は `export` で `web/` から作り直すので、正本の `web/` だけ直せばよい。

## 段階

各段階は単独でマージでき、終わった時点で画面が壊れていない状態にする。

```
段階 0（AI が書くものを英語に）── 独立。すぐ行える
段階 1（約束事の切り離し）─┐
                          ├─ 段階 2（仕組み）─┬─ 段階 3（盤面）─ 段階 4（カード）
                          │                  ├─ 段階 5（play.js）
                          │                  └─ 段階 6（サイト・エラー）
段階 7（AI の出力の言語。任意）── 段階 2 の後ならいつでも
```

段階 0 と 1 は画面の見た目を変えない。段階 1 は段階 5（下書きの行の文を訳す）の前提。

### 段階 0: AI が卓に書くもの（Note・カウンター・トークン名）を英語に統一する（済み）

翻訳はしない。Note は審判が後の判定で読み返す作業メモで、画面に出す文と判定に使う文を常に同じにしておくため
（訳した表示と審判の判断がずれることを避ける）。英語はオラクルと同じ言語なので、審判が読み返すときにも一番正確。
今の英語と日本語の混在もここで止まる。

- 審判のプロンプト（`prompts/judge.md`）に「カウンターの種類（`counter_add` の `kind`）・Note（`note_add` / `note_update` の `text`）・
  トークン名（`create` の `name`）は英語で書く。カウンターの種類は英語の正式な語を小文字で（`+1/+1`・`loyalty`・`defense`・`poison` …）」を足す
- AI の席のプロンプト（`player.md`。`player_intent.md` の席は卓に書かないので対象外）と、Claude Code で回すときの `.claude/skills/mtg-playtest/SKILL.md` にも同じ指示
  （どちらも既に Note の書き方の節がある）
- 画面は書かれたとおりに出す（Note の中のカード名も置き換えない）。言語を切り替えても変わらない
- 古い対局の記録（日本語の Note）は書き換えない
- テスト: プロンプトに英語の指示が入ること（`tests/test_prompt.py`）

ペンディング（今は行わない）: 表示の時の辞書による翻訳（カウンターの種類・`until`・`mana:`・トークン名）、
Note の中の `<英語名>` の日本語名への置き換え、構造化した Note（`kind`）。必要になったら見直す。

### 段階 1: 約束事を言語から切り離す（見た目は変わらない）

翻訳の前提。文の言語が変わっても動きが変わらないようにする。

- 下書きの行に構造のフラグを持たせる（例: `tap_source: true`・`untap: true`・`no_tap: true`）。`preview` は文ではなくフラグを見る。
  localStorage に残った古い下書き（フラグ無し）は今の正規表現で読む後方互換を一段階だけ残す
- 依頼の `then` と「行動の有無」「ブロックしない」を、文の中の印ではなく request の JSON のフィールドで送る。
  `request_then`・`_no_action` はフィールドを優先し、無ければ今の文から読む（既存の対局の記録を読めるように）
- サーバーが書くラベル（自動パス・投了・発言・審判）に機械が読む `kind` を足し、判定は `kind` で行う。文は表示用
- `worker.py` の `"決着"` を定数（言語に依らない値）に
- テスト: 既存の `tests/` と `tests/web.test.mjs` が通ること＋フラグ・フィールドで判定するテストを足す

### 段階 2: 仕組みと、ヘッダー・共通部分

- `web/i18n.js` を足す: `t(key, params)`・`lang()`・`setLang()`・言語の決め方（localStorage → `navigator.language` → `en`）。
  辞書は `web/i18n/ja.js`・`web/i18n/en.js`（ビルド無しの ES modules のまま。キーが片方に無ければもう一方 → キーそのもの）
- `index.html` の静的な文言は `data-i18n`（`title` は `data-i18n-title`）で印を付け、起動時と切り替え時に差し替える。`<html lang>` も替える
- ヘッダーに言語の切り替え（`日本語 / English`）。切り替えたら再描画（盤面・ページの `show` をやり直す。リロードはしない）
- 対象: `index.html`・`site.js`・`app.js`・`dom.js`・トースト
- テスト: `web.test.mjs` に辞書のキーが両方の言語でそろっているかの検査（片方だけのキーを失敗にする）

### 段階 3: 盤面（観戦）

- `render.js`: ゾーン名・フェイズ／ステップ名（`STEP_JA` などを辞書へ）・戦闘・スタック・Log の見出し
- カウンター・Note・トークン名は段階 0 のとおり書かれたまま出す（`${k} ×${n}` などの組み立てだけ辞書に）
- `motion.js`・`timeline.js` は文言なし
- この段階で観戦ビューア（静的書き出し `docs/` を含む）が英語で一通り見られる

### 段階 4: カード名・オラクル・画像

英語名を正本（識別子）のまま変えず、日本語は表示の時だけ重ねる。卓の状態・デッキ・AI に渡すもの・審判に送る
依頼の文はすべて英語名のまま。日本語のカードの情報が無ければ英語にフォールバックする。

- `carddb.py`: カードごとに日本語版の印刷（Scryfall の `lang:ja`。`/cards/search?q=!"<英語名>" lang:ja&unique=prints`
  の最新の1枚）から `printed_name`・`printed_type_line`・`printed_text`・画像（`image_uris.normal`）を取り、
  英語のキャッシュとは別のファイル（`cards/ja/<名前>-<hash>.json`。日本語版が無いカードは「無い」ことも残す）に置く。
  AI 用の `lookup`・`format_card` は変えない
- API: `/api/oracle?name=&lang=ja` は `{name, type_line, text, lang}`（日本語が無ければ `lang: "en"` で英語）、
  `/api/image?name=&lang=ja` は日本語の画像（無ければ英語）。`/api/names?lang=ja` で、対局に出てくるカードの
  英語名 → 日本語名の表をまとめて返す（盤面の描画のたびに1枚ずつ引かない）
- 画面（`source.js`・`render.js`）: カード名の表示・`alt`・`title`・カードの詳細・スタック・束の一番上を、表の名前に。
  Log・宣言・吹き出し・下書きの行の文の中の `<英語名>` も、表示の時に `<日本語名>` に置き換える（文そのものは変えない）。
  **Note・カウンター・トークン名は置き換えない**（段階 0）。並べ替え（`localeCompare`）も表示の名前で
- カードの詳細: 日本語のときは日本語の文を出し、「英語のオラクル」を開けるようにする。日本語の文は **印刷時の文で、
  エラッタ後のオラクルと違うことがある** と小さく添える（判定は英語のオラクルで行われるため）
- 静的書き出し（`export`）: `data/cards.json` に日本語名・日本語の画像の URL も入れる。オラクルは `scryfallOracle` が
  `lang` に応じて日本語版を引く
- 画像の言語は文言の言語に合わせる（別の切り替えは作らない。要望があれば足す）

デッキ登録の日本語名の入力（任意。この段階の後半か別の PR）:

- デッキリストに日本語名を書けるようにする。`/cards/collection` は日本語名を引けないので、`decks.check` が英語で
  見つからなかった名前を `/cards/search?q=lang:ja !"<日本語名>"` で引き直し、英語名に直して保存する
  （保存するデッキリストは英語名。検査の結果に「<日本語名> → <英語名>」を出す）
- Scryfall への問い合わせが増えるので、`ratelimit` の `deck_check` の数え方を見直す

### 段階 5: GUI の対局（`play.js`）

最も量が多い。段階 1 で約束事が外れているので、文を訳しても動きは変わらない。

- メニュー・操作パネル・止める場所・下書きの行の文（`summarize`・`THEN_JA`・`thenLabel` など）を辞書へ
- 下書きの行の文は審判（LLM）が読む。英語の文でも審判は読めるが、段階 7 までは審判の返答は日本語のまま
- 行の文の中のカード名は英語名（`<Name>`）のまま作り、表示は段階 4 の置き換えで日本語名にする
- 必要なら `play.js` を分ける（例: 行の文を作る部分を `lines.js` に）。量が多いので、この段階をさらに 2 つ（メニュー／パネル）に分けてよい

### 段階 6: サイトのページとサーバーのエラー

- `lobby.js`・`history.js`・`decks.js` を辞書へ
- サーバーのエラーは `{"error": "<日本語>", "code": "<キー>", "params": {...}}` にし、画面は `code` があれば辞書で、無ければ `error` をそのまま出す。
  `code` はユーザーに見える例外から順に足す（デッキの検査の行ごとの理由・レート制限・見られない対局・招待の期限など）
- デッキの検査（`decks.py`）の理由も `code` 付きに
- `legal.js`（利用規約・プライバシー）: 法的な文なので機械的には訳さない。英語版は運営者が確認した文を別に用意し、
  用意できるまでは「日本語版が正本です」と添えて日本語を出す

### 段階 7: AI の出力の言語（任意）

- 対局を作るときに言語（`lang`）を対局の設定に持たせ、プロンプトに「人に向けた文（宣言・ラベル・質問）は <言語> で書く」を足す。
  卓に書くもの（Note・カウンター・トークン名）は段階 0 のとおり英語のまま
- プロンプト本体は日本語のまま（審判の精度を変えないため）。英語のプロンプトに書き直すかは結果を見て判断する
- 人と人の対局で言語が違う場合は、文を書く席の言語（審判は対局の作成者の言語）にする
- `tests/test_prompt.py`・`test_llm.py` に言語の指示が入ることのテスト

### 対象外（この計画では扱わない）

- CLI（`cli.py`）・README・`design/`・`.claude/skills` の日本語（開発者向け。段階 0 の英語の指示を足すのは除く）
- AI・審判に渡すカード情報の日本語化（判定は英語のオラクルのまま）
- AI が書く Note・カウンター・トークン名の翻訳（表示の辞書翻訳も含めてペンディング。段階 0）

## 決めたこと・決めること

- 決めた: 言語は en / ja の 2 つ。既定はブラウザの言語、ヘッダーで切り替え、localStorage に保存
- 決めた: 翻訳ライブラリは使わない（ビルド不要の ES modules の方針に合わせ、小さな `t()` を自作）
- 決めた: 卓に書くもの・AI に渡すものは言語に依らない形。翻訳は表示の時だけ
- 決めた: カードは英語名が正本。日本語名・日本語の文・日本語の画像は表示の時だけ重ね、無ければ英語
- 決めた: AI が卓に書くカウンター・Note・トークン名は翻訳せず英語で統一。表示の辞書翻訳はペンディング
- 決める: 段階 6 のエラーで `code` を付ける範囲（全部か、利用者がよく見るものだけか）
- 決める: 段階 7 を行うか、行うなら英語のプロンプトまで作るか
- 決める: デッキ登録の日本語名の入力を段階 4 に入れるか、後に回すか
- 決める: 日本語版が出ていないカード（日本語の印刷が無い）を英語で出すことでよいか
- 決める: 利用規約・プライバシーの英語版を誰が用意するか
