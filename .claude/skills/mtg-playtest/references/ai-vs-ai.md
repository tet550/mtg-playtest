# AI同士の軽量テストプレイ（既定）

開始時はこのファイル、[保存先](storage-layout.md)、[実行中の記録](log-format.md)、使うデッキの方針だけ読む。
各リンク先をまとめて先読みしない。[資料の総目次](index.md)は行き先が分からない場合に使う。

## 情報と判断

単一AI・両手札共有。席別view・--as・サブエージェントは使わない。相手の手札に合わせた最適化を極力避け、両席のキープ基準と方針を最初に固定する。未公開のライブラリー順は読まない。

## 開始から初手確認

1. プロジェクト直下で実行する。`deck show <登録名> --brief`で対象2デッキを確認。方針のパスが出たら開始用の本文を読む。分冊の追加資料は指定された判断の前に読む。登録済みで変更がなければ再登録・全件検証しない。新規・変更は`deck add <file> --quiet`で検証して警告を解消する。
2. [保存先の規約](storage-layout.md)に従って、現地日時・席順で未使用の対局フォルダを選ぶ。`--state`と`--results`をその中に置く。各ゲームの状態とseedは別、結果ファイルは共通。独立した連戦は先手交互、マッチ形式は前ゲーム敗者が選ぶ。
3. `init --deck1 <登録名またはパス> --deck2 <登録名またはパス> --seed <値> --first random --history-hand both`。両メイン・サイドの不足キャッシュを自動取得し、未取得なら状態未保存で停止。有効なキャッシュは再取得しない。`--offline`は完備時のみ開始可。
4. 初手は次のバッチで配り、**名前付き表示を読んでから**キープ・マリガンを判断する。先手T1の通常ドローは飛ばす。

```text
draw P1 7
draw P2 7
show --hand both
```

5. **マリガンで引き直すたびに`show --hand both`で名前とOIDを再確認してから判断する。** 引き直す操作とその結果に依存するキープ判断を同じバッチへ先回りして入れない。キープ後に規定枚数をボトムへ送り、確定手札を名前付きで確認する。回数・キープ枚数を記録する。未知の構文だけ`mulligan -h`／`bottom -h`で確認する。

## 通常の進行

- 既知の確定操作を`run - --compact`へまとめる。入力はCLIが連番保存し、1行ごとの保存・undo・全証跡を保持する。ドロー・探索・乱数・新規IDなど、結果で判断が変わる所で区切る。エラーで止め、成功済みの行を再実行しない。`--keep-going`は使わない。
- バッチ末尾は`show --ids --packed --hand both`を1回。`--packed`は手札の余白と行数だけを減らし、コスト・タイプ・P/Tを保持する。P/T・カウンター・タップ・酔い・能力・装着先など、名前以外は全文確認する。新しい対応はdraw/token等で読み、曖昧になったら`show --hand both`へ戻す。再開時も名前付き全文。差分`--delta`は利用者が明示的に選んだ場合だけ。
- コスト・マナ用途制限・対象・優先権・応答・誘発・解決ごとのSBAを省略しない。未知のカードだけ`card show <名前>`で本文確認し、同じ文脈で再読しない。未取得表示なら取得してから判断する。
- 誘発は`pending`、装備効果は`fx`、関連追放は`linked`を使う。初使用前に下の該当資料を読む。`stack resolve`だけでは除去されず、効果適用後にカードはmove、通常の能力はstack pop。台帳の能力はpending resolveで完了させる。
- 通常の次ターンは`turn next --to precombat_main --draw`。明示的なステップ誘発・英雄譚・予約の候補があれば途中で止まり、runの後続行も未実行になる。`pending list`のreviewを[確認・予約の手順](bookkeeping.md#タイミングの確認と予約)で処理してから、残りをphaseで続ける。検出対象外の判断は手前で自分で止める。`phase`は引かない。既に引いたカードを二重に引かず、同じターンの進行にturn nextを繰り返さない。
- `note`は方針・重要分岐・裁定・収支・補正だけ。重要イベントE/Rの根拠は[記録規約](log-format.md)に従い、その場で記録する。数ターン単位の進捗は新しい重要事項だけ。
- 人向けの名前付き盤面は`output/<state名>/turn-starts.md`へ自動保存。初手・マリガン後のT1進行時、以降はアンタップ後・通常ドロー前。undoは訂正を追記する。`run --compact`のOID表示には証跡の`named_stdout`も残る。
