## このスキルの役割

テキスト上でMTGの対戦を進行し、ルール的に正しい盤面推移を再現する。
デッキの回り、カードのバランス、特定の盤面の解決を検証するために使う。

**厳密さが価値の源泉**。「たぶんこうなる」で流すとテストプレイの結論が信用できなくなる。
判断に迷ったら推測で埋めず、後述の手順で必ず一次情報を引く。

## 3つのモード

最初に必ずどのモードかを確定させる。ユーザーが明示していなければ一言で聞く。
モードによって「誰が意思決定するか」が変わり、そこを取り違えると勝手に手を進めてしまう。

| モード | 誰が操作するか | 使う場面 |
|---|---|---|
| **A. 対人プレイ** | ユーザー＝プレイヤー1／Claude＝プレイヤー2＋ジャッジ | 1手ずつ確認しながら回したい |
| **B. 自動シミュレート** | Claude が両者を操作 | デッキ2つを最後まで回す、複数回まわして傾向を見る |
| **C. 盤面ジャッジ** | 操作なし | 「この盤面でこうしたらどうなる？」の解決だけ |

### A. 対人プレイ

- ユーザーの手札・ライブラリーは**ユーザーに見せる**。Claude側の手札は伏せ、枚数のみ公開する
- **マリガンは必ずユーザーに宣言させる。** 初手7枚を配ったら、そこで止まって
  キープ／マリガンを聞く。自分側だけ処理して第1ターンに進んではいけない。
  マリガンは優先権ではないので「対応の余地がないステップ」の例外に含まれない。
  ゲーム2以降のセットアップで流し込みがちなので特に注意する
  （やってしまったら、同じ seed で `init` し直せば初手はそのまま再現できる）
- **隠匿情報を平文でログに残さない**。`log` はユーザーからも読めるので、そこに Claude 側の
  手札が書かれていると、伏せているつもりの情報が筒抜けになる。専用の口を使うこと：
  - 自分（Claude側）のドロー … `draw P2 1 --quiet` — 標準出力とログの両方でカード名を伏せる
  - **ターン進行に乗せたドロー … `turn next --to precombat_main --draw --quiet`**。
    `--quiet` を落とすと自分のドローが平文で出る。**最も踏みやすい漏洩経路**なので、
    自分のターンを始めるコマンドには機械的に `--quiet` を付ける
  - **マリガン … `mulligan P2 --quiet` → `bottom P2 <oid...> --quiet`**。
    どちらも既定では引き直した7枚・下に置いた札を平文で出す
  - 自分の手札についてのメモ … `note "..." --private P2`
  - `log` の既定は P1 視点で、秘匿マーク付きの行を出さない。`--player P2` / `--all` で見える
  - 中身の確認は `hand P2` で行う（これは表示するだけでログに残らない）
  - **`run` に渡すコマンド・ファイルの中身も見る。** `show --hand both` が1行でも入っていると
    そこで全部出る。生成器（`pizza_recipe.py` など）の出力は流す前に末尾を確認する

**自分側で `--quiet` が要るのは `draw` / `turn --draw` / `mulligan` / `bottom` の4つ。**
迷ったら付ける（付けても盤面は変わらない）。漏らしてしまったら、乱数を消費し直せる操作
（マリガンの引き直しなど）なら `undo` してやり直せるが、ライブラリー上からのドローは
`undo` しても同じカードが出るので**隠し直せない**。ユーザーに一言報告して続行する。

**ゲーム2以降（サイドボード後）**：入れ替え後の60枚を対局フォルダに
`g02-<略称>.txt` として書き、`init --deck2 <そのパス> --deck2-name <素の構築の登録名>`
で始める。**`deck add` で登録しない**（登録を増やすと `stats` が同じデッキを別行で数える。
規定は [storage-layout.md](storage-layout.md)）。入れ替えの計画は
`decklists/strategy/<登録名>.md` の「サイドボード」節（あれば）。
先手・後手は**直前のゲームの敗者が選ぶ**。
サイドボードの内容は隠匿情報なので、枚数だけ伝えてゲーム終了後に開示する
（`init` はリストを表示しないので `--quiet` は要らない）。
- ユーザーが優先権を持つタイミングは**勝手に飛ばさない**。ただし「対応可能なカードが手札にない」
  「マナが出せない」等、選択の余地がないステップはまとめて進めてよい（進めたことは書く）
- ユーザーの操作がルール違反なら、実行せず理由を示して差し戻す。黙って直さない
- Claude側のプレイングは、開始時に方針（アグロ寄り／コントロール寄り等）を宣言してから一貫させる。
  ただし `init` が `方針: <席> = decklists/strategy/<登録名>.md` を出したら、**その文書が優先**。
  最初のプレイ判断より前に読み、宣言はその内容に沿わせる

### B. 自動シミュレート

[ai-vs-ai.md](ai-vs-ai.md) を優先する。対人向けの表示・確認手順は自動対戦には適用しない。

### C. 盤面ジャッジ

ゲームを進行させず、**処理順**と**結果**だけを返す。形式:

1. その行動でスタックに何が乗るか（順番）
2. 各プレイヤーが応答できるタイミング
3. 解決順と、その都度の状況起因処理
4. 最終的な盤面
5. 判断の根拠（総合ルールの番号やカードのオラクル・テキスト）

ルール解釈が割れうる箇所は、断定せず「A解釈／B解釈」を併記してユーザーに確認する。
