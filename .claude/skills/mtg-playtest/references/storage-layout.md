# playtest保存先の共通規定

新しい対局・連戦の保存先を決めるときに一度読む。ユーザーが保存先を明示した場合はその指定を優先する。既存対局の再開・調査では元の保存先を使う。

## フォルダ名

`playtest/YYYYMMDD-hhmm-<format>-<p1>-vs-<p2>/`

- 日付・時刻：**作成時点のユーザー現地日時**（24時制、`date +%Y%m%d-%H%M` 等で取得する）。開始日時のまま固定し、途中で日付が変わっても改名しない。seedの数値を日付・時刻として使わない。
- format：単発BO1は`bo1`、BO3マッチは`bo3`、独立した複数ゲームの連戦は`series`。
- p1／p2：席順のデッキ略称。先手順・勝者順ではない。先手交代やサイド変更でも改名しない。
- 名前は半角英小文字・数字・ハイフンのみ。`sim`、`sim2`、`new`、`final`のように内容を特定できない名前を新規対局に使わない。
- **作成前に必ず `ls playtest/` で同名の有無を確認する。** `mkdir -p` は既存ディレクトリを黙って受け入れ、`init --state <既存ファイル>` は既存の状態ファイルと操作バッチを警告なく上書きするため、確認を飛ばすと**別依頼の対局を破壊する**。
- 同じ分に2件作ることになった場合（同名が既にある場合）だけ、末尾に`-02`から連番を付ける（例：`20260910-1216-bo1-dw-vs-piza-02`）。既存フォルダへ後から書き足さない。

例：

```text
20260909-1035-bo1-dw-vs-piza
20260909-1412-bo1-dw-vs-piza
20260909-1412-bo1-dw-vs-piza-02
20260909-1830-bo3-dw-vs-piza
20260909-2005-series-tokens-vs-piza
```

seed・実行モード・デッキ版・勝敗はreport.mdに記録し、フォルダ名には重ねない。再現実験や分岐を新たに走らせる場合もその時刻で新しいフォルダを作り、report.mdに元のフォルダ・ゲーム・分岐点を記す。同じseedでも新規実行と再開を混同しない。

## デッキ略称

| 登録名 | 略称 |
|---|---|
| ボロスドワーフ | dw |
| Boros Tokens | tokens |
| mono-green-landfall | green |
| piza | piza |

新しいデッキは初回に短く一意な英小文字の略称を決め、この表へ追記して以後固定する。登録ファイル末尾のハッシュや、その場限りの略し方を使わない。サイド後の派生登録は同じデッキ略称を使い、正確な登録名・版はreport.mdで区別する。

## 中身の名前

1フォルダに1回の依頼による対局・マッチ・連戦を保存する。同じ連戦の各ゲームはフォルダを分けない。

```text
<対局フォルダ>/
  g01.json                 # 状態。g02.json、g03.json…
  g01-001.mtg              # 操作バッチ。ゲームごとに001から連番
  results.jsonl            # この実行の共通結果
  report.md                # 条件・ゲーム別結果・参照・訂正
  findings.md              # 実行上の問題がある場合だけ
  history/g01/             # CLIが生成するundo履歴
  output/g01/run-*.jsonl   # CLIが生成する証跡。名前を変更しない
  audit.jsonl              # CLIが必要時に生成
```

修正・生成器のバッチも次の未使用番号にする（例：g01-008.mtg）。実行済みバッチを上書きしない。`--state`と`--results`はこのフォルダ内を明示し、playtest直下へ状態や結果を散在させない。`shuffle.py`の出力もプレイ記録なので`--out`でこのフォルダを明示し、リポジトリ直下へ置かない。空のreport・findings・履歴フォルダを先に量産しない。

対局を伴わない検証・ベンチマークの一時データはOSの一時領域を使う。残す検証成果は`playtest/_checks/YYYYMMDD-hhmm-<topic>/`にまとめ、実戦のresults.jsonlと混ぜない。

既存のsim2や、時刻を含まない旧形式（`YYYYMMDD-<format>-<p1>-vs-<p2>-<NN>`）・日付・デッキの順が異なるフォルダは遡って改名しない。移行を明示依頼された場合に限り、関連する参照を確認して更新する。
