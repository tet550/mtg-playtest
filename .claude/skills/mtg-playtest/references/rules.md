# MTG 基本ルール（Table Engine で回すための要点）

エンジンはルールを判定しないので、ここに書いた処理はすべて AI が Operation で行う。
正確な規定は総合ルール（Comprehensive Rules, CR）。迷ったらカードのオラクルと CR を優先し、
このファイルの要約で押し切らない。各項の「→」は mtgtable での書き方。

## ゲームの開始

- ライフ20、手札7枚。先攻は最初のターンのドローを飛ばす
- 順番（総合ルール 103）: 手札を引く → 全員のマリガンを終える → 開始時の手札からの行動（Leyline 系。先攻 → ターン順）
  → 先攻の T1。ここまでは **ゲーム前**（mtgtable では turn 0 / `pregame`。`step to=untap` で T1 へ）
- マリガン（ロンドン）: 手札をライブラリーに戻して切り直し7枚引く。キープしたら、マリガンした回数だけ
  手札を好きに選んでライブラリーの一番下に置く
  → `declare kind=mulligan` → `move {zone: hand, all} to library` → `shuffle` → `draw 7`、キープ時に `move ... position: bottom`

## ターンの構造

| フェイズ | ステップ | ターン起因処理（自動で起きること） | 優先権 |
|---|---|---|---|
| 開始 | アンタップ | アクティブ・プレイヤーのパーマネントをアンタップ | なし |
| | アップキープ | （「アップキープの開始時に」の誘発） | あり |
| | ドロー | アクティブ・プレイヤーが1枚引く | あり |
| 第1メイン | | 土地のプレイ・ソーサリー速度の行動ができる | あり |
| 戦闘 | 開始 | | あり |
| | 攻撃クリーチャー指定 | アクティブ・プレイヤーが攻撃クリーチャーを選ぶ（警戒以外はタップ） | あり |
| | ブロック・クリーチャー指定 | 防御プレイヤーがブロックを選ぶ | あり |
| | 戦闘ダメージ | 先制攻撃・二段攻撃がいれば先制攻撃ダメージ・ステップが先に入る | あり |
| | 終了 | | あり |
| 第2メイン | | | あり |
| 終了 | 終了 | （「終了ステップの開始時に」の誘発） | あり |
| | クリンナップ | 手札を上限（7）まで捨てる → ダメージが消え、「ターン終了時まで」の効果が同時に終わる | 通常なし |

- 土地のプレイ: 自分のメイン・フェイズ、スタックが空、自分が優先権を持つとき、1ターンに1回（特別な処理でスタックを使わない）
- ソーサリー速度（ソーサリー・クリーチャー等の呪文、「ソーサリーとしてのみ起動できる」能力）: 自分のメイン・フェイズで、スタックが空のとき
- 各ステップ・フェイズの終わりに、マナ・プールのマナは消える
- クリンナップで状況起因処理や誘発が起きたら、優先権が発生し、もう一度クリンナップをやり直す
- 攻撃クリーチャーがいなければ、ブロック指定と戦闘ダメージのステップは飛ばす
  → `step {to: ...}` で名前指定。アンタップは `untap_all`、ドローは `draw`、マナの消滅は `mana_clear`、
  クリンナップは `note_remove {until: "end_of_turn"}` と手札の上限を AI が行う

## 優先権とスタック

- 各ステップ（アンタップ・クリンナップ以外）で、まずアクティブ・プレイヤーが優先権を得る
- 呪文を唱える・能力を起動すると、その Player がまた優先権を得る（続けて何かできる）
- **全員が続けてパス**したら: スタックが空でなければ一番上が解決し、アクティブ・プレイヤーが優先権を得る。
  スタックが空ならそのステップ（フェイズ）が終わる
- 誘発型能力は、次に誰かが優先権を得るときにスタックに積む。同時に誘発したら、アクティブ・プレイヤーの分から
  先に積む（APNAP）。自分の分の順番は自分で決める（後に積んだものが先に解決する）
  → `stack_push` → `pass`（相手が継続的なパスなら自動で回る）→ 全員パスで `stack_remove`。
  誘発の順番は積む順で決め、後から変えるなら `stack_move`

## 呪文を唱える

順番（CR 601.2）: 1. 公開してスタックへ動かす → 2. モード・X・追加コストなどの選択 → 3. 対象を選ぶ →
4. 総コストを決める（追加・代替コスト、増減） → 5. マナ能力を起動 → 6. コストを支払う（順不同）。

- 生け贄・捨てる・タップなどをコストとして含む場合、支払いは唱える途中で起きる（対応される前）
- インスタントと瞬速を持つものは、優先権があればいつでも唱えられる
- 唱えられるか（タイミング・コストが払えるか・対象が適正か）の判断は AI が行う
  → `tap` → `mana_add` → `mana_spend` → コストの生け贄は `move ... to graveyard` → `stack_push {card, targets}` → `pass`

## 能力

- **起動型**（「コスト: 効果」）: 優先権があれば起動できる（制限があればそれに従う）。コストに `{T}` を含む
  クリーチャーは、召喚酔い（自分の直近のターンの開始時からコントロールしていない）なら起動できない
- **マナ能力**: マナを生み、対象を取らない起動型・誘発型能力。**スタックを使わず**すぐ解決する。対応できない
  → `tap` + `mana_add` だけ（`stack_push` しない）
- **誘発型**（「〜とき」「〜たび」「〜の開始時に」）: 条件を満たすと誘発し、スタックに積まれる。
  「〜なら」を含む（if 節の）誘発は、誘発時と解決時の両方で条件を確かめる
- **常在型**: 戦場にある間ずっと効いている。スタックを使わない
- **忠誠度能力**: 1ターンに1回、ソーサリー速度で、プレインズウォーカー1体につき1つ

## 解決

- 解決時に対象の適正さを確かめ直す。**すべての対象が不適正**なら何もせずに終わる（打ち消されるのと同じ扱い）。
  一部だけ不適正なら、適正な対象にだけ効果を及ぼす
- インスタント・ソーサリーは解決後に墓地へ。パーマネント呪文は戦場に出る
- 打ち消された呪文は墓地へ
  → 解決は `stack_remove {card_to: graveyard | battlefield}`。打ち消しも `stack_remove {card_to: graveyard}`

## 状況起因処理

誰かが優先権を得る直前に、次をまとめて同時に確かめる（起きなくなるまで繰り返す）。**エンジンは行わないので、
優先権が動く前に毎回 AI が確かめる**。

- ライフ0以下 → 敗北。ライブラリーが空で引こうとしていた → 敗北。毒カウンター10以上 → 敗北
- タフネス0以下のクリーチャー → 墓地（破壊ではない。破壊不能でも防げない）
- 致死ダメージ（タフネス以上のダメージ）を受けているクリーチャー、接死のダメージを受けたクリーチャー → 破壊
- 忠誠度0のプレインズウォーカー、守備値0のバトル → 墓地
- 同じ名前の伝説のパーマネントを2つ以上 → 1つを残して墓地（レジェンド・ルール）
- 付けられないオーラ → 墓地。不正な装備・城砦 → はずれる
- 戦場以外にあるトークン → 消える。スタック・戦場以外にある呪文のコピー → 消える
- 同じパーマネントの +1/+1 と -1/-1 カウンター → 同じ数ずつ取り除く
  → 敗北は `player_set {status: lost}`、墓地へは `move`、トークンの消滅は `remove`、相殺は `counter_remove`

## 戦闘

- 攻撃できるのは、召喚酔いでない（または速攻を持つ）アンタップのクリーチャー。攻撃先は相手・相手の
  プレインズウォーカー・相手が守るバトル
- ブロックできるのはアンタップのクリーチャー（召喚酔いでもよい）。1体が複数の攻撃クリーチャーをブロックするには
  それを許す効果が要る。1体の攻撃クリーチャーを複数でブロックしてよい
- ブロックされた攻撃クリーチャーは、ブロッカーが取り除かれてもブロックされたまま（トランプル以外はダメージを与えない）
- ダメージの割り振り: 複数にブロックされた攻撃クリーチャーは、ダメージをブロッカーの間で自由に割り振る
- トランプル: ブロッカー全員に致死ダメージ（接死なら1点で致死）を割り振れば、残りをプレイヤーなどへ
- 先制攻撃・二段攻撃: 先制攻撃ダメージ・ステップで先に与える（二段攻撃は両方のステップで与える）
- 戦闘ダメージは同時。受けたダメージはクリンナップまで残る
  → `attack {tap: true}`（警戒は付けない）→ ブロックは防御側の判断で `block` → ダメージはプレイヤーなら `life`、
  クリーチャーなら Note（`damage 3`, `until: end_of_turn`）で記録し、状況起因処理を確かめる。
  先制攻撃があるときは `turn_set {phase: combat, step: first_strike_damage}` → `turn_set {step: combat_damage}`。
  終了ステップで `combat_clear`

## 領域の移動とオブジェクト

- 領域を移ったカードは、前とは関係のない新しいオブジェクトになる（CR 400.7）。カウンター・付いていたオーラ・
  「ターン終了時まで」の修整などは引き継がない
- 戦場に出るパーマネントは、特に書いてなければアンタップで出る。出たターンは召喚酔い
- トークンは戦場を離れると（墓地などに一度置かれてから）消える
- コピーはコピー可能な値（名前・コスト・タイプ・能力・P/T など印刷されたものと、他のコピー効果）だけを写す。
  カウンター・タップ状態・修整・オーラは写さない。コピーのコピーは元と同じ値になる
- 「破壊」は破壊不能で防げる。「生け贄」「追放」「タフネス0以下」は防げない
  → `create {copy_of}`。生け贄は `move ... to graveyard`（トークンは能力を積んだ後に `remove`）

## 継続的効果・置換効果

- 置換効果（「代わりに」「〜状態で戦場に出る」）はイベントを書き換える。1つのイベントに同じ置換効果は1回だけ
- 継続的効果は種類別の順（レイヤー）で適用する: 1 コピー → 2 コントロール → 3 文章 → 4 タイプ → 5 色 → 6 能力 →
  7 P/T（7a 特性定義 → 7b 基本 P/T を定める効果 → 7c 修整とカウンター → 7d P/T の入れ替え）。
  同じレイヤー内はタイムスタンプ順（依存関係があればそちらが優先）
- 「ターン終了時まで」はクリンナップで終わる
  → P/T 修整は Note。同じ効果が重なるときは1枚にまとめて `note_update`。P/T の最終値は AI が計算する

## よく使うキーワード

| キーワード | 要点 |
|---|---|
| 速攻 | 召喚酔いでも攻撃・`{T}` 能力の起動ができる |
| 警戒 | 攻撃してもタップしない |
| 飛行 / 到達 | 飛行はブロックされにくい（飛行か到達を持つものだけがブロックできる） |
| 威迫 | 2体以上でしかブロックされない |
| トランプル | 余ったダメージを貫通させる |
| 接死 | 1点でも与えたクリーチャーを破壊する（状況起因処理） |
| 絆魂 | 与えたダメージ分ライフを得る（ダメージと同時） |
| 先制攻撃 / 二段攻撃 | 上の「戦闘」を参照 |
| 破壊不能 | 破壊されない（致死ダメージでも）。タフネス0以下・生け贄・追放は防げない |
| 呪禁 / 護法 | 相手の呪文・能力の対象にならない / 対象にされたら、追加コストを払わないと打ち消す（誘発型能力） |
| 瞬速 | インスタントのタイミングで唱えられる |
| 占術 N | 上から N 枚を見て、好きな枚数を好きな順で下へ、残りを好きな順で上へ |
| 諜報 N | 上から N 枚を見て、好きな枚数を墓地へ、残りを好きな順で上へ |
| 切削 N | 上から N 枚を墓地へ |

## 間違えやすい点

- マナ能力はスタックに積まない。マナ・プールはステップの終わりに消える
- ダメージとライフの喪失は別（絆魂・「ダメージを与えたとき」はダメージだけ）
- 「引く」と「手札に加える」は別（引いたときの誘発は「引く」だけ）
- 呪文の対象は唱えるときに選ぶ。後から変えない
- 手札・ライブラリーは非公開。相手の手札を知っていても、その Player が知らない情報で判断しない
- 先攻の最初のターンはドローしない
- 召喚酔いは「このターンの開始時からコントロールしているか」。速攻が無ければ、出たターンは攻撃も `{T}` 起動もできない
