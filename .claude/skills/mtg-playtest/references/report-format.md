## 保存版の固定書式

連戦の冒頭に方式、P1/P2とデッキ名、使用デッキの版または保存先、先手の決め方、結果ファイルを一度書く。各ゲームは次の順序。山括弧内は実測値・実在パスに置き換える。

```text
### G01
条件: seed=<値> | 先手=P1 | キープ=P1 <枚数>/P2 <枚数> | state=g01.json

- E01 T<通算> P<行動席> <フェイズ/応答>: <行動と結果>。［R1:<行範囲>］

結果: <勝者/引分/中断> | <通常決着/投了/未決着> | T<通算> P<アクティブ席>（<先後><何ターン目>） | ライフ=P1 <値>/P2 <値>
所見: <主な要因を1文。推測は明示>。根拠=E01。
検証: <未解決の疑義なし/補正あり・集計可/保留・集計除外>（<必要な理由>）

参照:
R1 = output/g01/<実在するrunファイル名>.jsonl
```

- TはCLIの通算ターン。イベントの席は行動者であり、相手ターンの応答もある。決着行にはアクティブ席と先後の何ターン目かを併記する。未決着は停止時点を書く。
- キープ欄にはマリガン回数も残す。サイド変更があれば該当ゲームにIN/OUTを枚数付きで追記する。デッキ名は素の構築の登録名で書き、サイド後の別名を作らない。読み込んだリストは`playtest/<対局>/g02-<略称>.txt`として示す。
- 同名個体や対象を区別するカードは`[oid]カード名`。oidはゲーム内で扱う。
- 通常は1イベント1行、1ゲーム3〜8イベントを目安にする。必要な情報を削る上限にはしない。所見がなければ「なし」とし、評価を創作しない。
## 保存版の機械検査

終了報告を保存したら `python .claude/skills/mtg-playtest/scripts/check_report.py <report.md>` を実行する。参照の存在・物理行範囲、同じディレクトリのresults.jsonlとseedで対応した勝者・通算ターン・最終ライフを確認する。seedの重複は曖昧として停止する。

可変パワーの反復には必要な場合だけ次の1行を加える：
`検算: power=6 pool=1 count=8 cost=5 final_power=22 final_pool=65`
この6項目の収支も検査する。任意の文章中の数字や裁定は検査しない。エラーが起きた場合は「構文検査で停止」「実行中のコマンド失敗」「未捕捉例外」を区別し、例外がなくても「エラーなし」と書かない。段階ごとのメモと最終値が異なるなら訂正対象にする。

## 草稿の生成

`run --compact`内の`note "説明" --event E01`（解決用の`--do`／`--file`内を除く）で記録したイベントは、次のコマンドで草稿へまとめられる。

```bash
python .claude/skills/mtg-playtest/scripts/report_draft.py playtest/<対局フォルダ> --game g01 --seed 123
```

既定の出力は`report-draft.md`。`--out`で同じ対局フォルダ直下の別名を指定できるが、既存ファイルは上書きしない。イベントの範囲は同一バッチの先頭（前イベントがあればその直後）から当該noteまでで、前のバッチへ遡らない。広い範囲や複数バッチをまたぐ出来事はAIが必要に応じて参照を補う。

seedで結果を照合し、現行状態の結果・ライフ・ターン・ログと確認する。手札・山札は出力しない。旧式noteからE番号を推定せず、イベントなし・重複・証跡範囲の失敗・undo/initを含む証跡・現行ログから消えたイベントは停止する。巻き戻しの訂正は従来どおり手動で確認する。

草稿はルール検証の代わりにならない。方式・キープ枚数・所見・検証結果を記入し、参照を確認してreport.mdに仕上げてからcheck_report.pyを実行する。
