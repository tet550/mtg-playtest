# 実行ブリーフ（jund-sacrifice vs piza）

**対局中にこのベンチマークから読んでよいのはこのファイルと [games.json](games.json)、同梱の
[decklists/](../decklists/) だけ。** `../expected/` 配下と `../score.py` は開かない。
期待値・過去の実測・合否条件を見てから回すと、その回は測定にならない。

## やること

同梱のデッキリスト2つを、`games.json` に並んだ seed と先手でそのまま回す。1ゲームずつ独立に、
[AI同士の軽量テストプレイ](../../../.claude/skills/mtg-playtest/references/ai-vs-ai.md)の手順どおりに進める。
ベンチマーク用の特別なプレイ方針・特別な記録は無い。**普段の対局と同じように回すことが条件そのもの**で、
普段と違うことをすると測っている対象が変わる。

- デッキは同梱スナップショットを `init --deck1 <path> --deck1-name jund-sacrifice --deck2 <path> --deck2-name piza`
  で読む。リポジトリ現行の `decklists/` は使わない（構築が変わっても基準値が有効なまま残るように固定してある）。
- 方針文書（`decklists/strategy/<登録名>.md`）は、`init` がパスを出したら普段どおり読む。無い席は自分で方針を決めて宣言する。
- バッチの切り方は[適正サイズ](../../../.claude/skills/mtg-playtest/references/ai-batches.md#バッチの適正サイズ)に従う。
- 決着したら `end --winner <席> --reason <理由> --tag <manifest の tag>`。投了は
  [投了条件](../../../.claude/skills/mtg-playtest/references/concede.md)を満たすときだけ。

## 守ること（測定条件）

1. **ゲーム間で学習しない。** 前のゲームの結果・敗因・「次はこう回す」をあとのゲームへ持ち込まない。
   seed ごとに、そのゲームで見えている情報だけで判断する。
2. **勝敗を作りにいかない。** どちらかを勝たせる／規定ターンに間に合わせるための不自然な判断をしない。
   ルール上あり得ない操作で辻褄を合わせない。
3. **記録を後から整形しない。** `note` の訂正・`undo`・バッチの切り方は、そのときに実際に必要だったぶんだけ残す。
   これらの痕跡自体が測定対象なので、きれいに見せるための事後編集は結果を壊す。
4. 途中でルールや処理に迷ったら、普段どおり該当資料とカード本文を読んで判断する。読んだこと自体は問題ない。

## 保存先

`setup.py` が作った実行フォルダ（`playtest/_checks/<日時>-bench-jund-vs-piza/`）の中だけを使う。
状態・操作バッチ・証跡・`results.jsonl` はすべてそこに入る。実戦の対局フォルダへ混ぜない。

## 終わったら

全ゲームの `end`（または `concede`）まで終えた時点で実行フェーズは終了。採点はここではやらない。
そのまま[採点手順](../../../.claude/skills/mtg-benchmark/SKILL.md#3-採点blind-解除)へ進む。
