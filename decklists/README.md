# decklists の規約

`decklists/*.txt` が**人が書く正本**。対局はこのファイルを直接読んで始める（`mtgtable`、[README](../README.md)）。

```bash
python -m mtgtable new playtest/g1 --deck p1=decklists/piza.txt --deck p2=decklists/jund-sacrifice.txt
```

```bash
python -m mtgtable deck decklists/piza.txt --fetch
```

## ここに置くもの / 置かないもの

**`decklists/` が持つのは素の構築（G1で使う75枚）だけ。**
サイド後の構成はマッチごとの記録なので置かない。計画は方針文書
（`strategy/<デッキ名>.md` の「サイドボード」節）、実際に使った60枚は対局フォルダ
（`playtest/<対局フォルダ>/`）に同じ書式で置く。

## ファイル名

`<デッキ名>.txt`（`piza.txt` / `boros-dwarves.txt`）。

- `<デッキ名>` は半角英小文字・数字・ハイフン。対局中の Player 名になる。

## 中身の書式

```text
# <デッキ名> — <一行説明>
# 出典: <URL・由来>                    ← あれば
# 方針: decklists/strategy/<デッキ名>.md ← 方針文書があれば

Deck
<クリーチャー>

<その他の呪文>

<土地>

Sideboard
<同じ並び>
```

- **カード名は英語名**（`oracle` コマンドが Scryfall の英語名で引く）。
  1ファイル内で日英が混ざらないよう、日本語印刷があるカードも英語名で書く。
- セット記号とコレクター番号（`(DFT) 218`）は書かない。パーサーは読み飛ばすが、
  書いてあるファイルと無いファイルが混在するだけになる。
- 並びは **クリーチャー → その他の呪文 → 土地**、各群はマナ総量→名前の順。
  群の間は空行で区切る（空行と `#` 行はパーサーが無視する）。
  素の構築とサイド後の diff がそのまま IN/OUT になるので、この順を崩さない。
- 見出しは `Deck` / `Sideboard`。`デッキ` / `サイドボード` も解釈されるが、書くときは英語で揃える。
- 対局フォルダに書くサイド後の60枚も同じ書式にする（ヘッダーは素の構築と IN/OUT を書く）。

## プレイ方針とサイドボード計画

`strategy/<デッキ名>.md` に置く。ファイル名はデッキ名と同じにする（`piza` → `strategy/piza.md`）。
そのデッキを使う AI は、最初のプレイ判断より前に読む。

長い方針は開始用の`<デッキ名>.md`と、`<デッキ名>-combo.md`／`<デッキ名>-sideboard.md`等へ分割できる。開始用にはキープ・基本展開・追加資料を読むタイミングとリンクを残す。

中身の書式は自由。デッキの狙い・始動手順・キープ基準・不利マッチでの方針など、
プレイ中に迷う判断を書く。
